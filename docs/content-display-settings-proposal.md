# 表紙・紹介文の表示設定案

2026年10月7日。表示制御を実装済み。スマホの提出用ビルド16に反映済み。管理画面の公開状況は末尾に記載。

## 目的

成人向けの本も個人の蔵書として登録・管理できる。公開ランキングの制限、個人画面の表示設定、ストアの年齢区分は別々に扱う。年齢別の機能変更は行わない。

## 表示設定

設定名の推奨は「表紙・紹介文を表示」。初期値はON。ただし未確認の表紙・紹介文はONでも表示しない。OFFでは本棚・シリーズ・欲しいリスト・登録確認・検索候補・自分のランキング・本の詳細の画像と紹介文を隠す。書名・作者・出版社・ISBN・巻数・所持・読書記録・購入リンクは残す。OFFにしてもデータは削除しない。

この設定は表示の好みを切り替えるもので、禁止対象の表紙・紹介文を解放する設定にはしない。「成人向け情報を無条件で表示」とは説明しない。

## 管理者の判定

本が成人向け専用かどうかと、掲載する表紙・紹介文に問題がないかは分ける。成人向けの本でも書名と蔵書記録を扱える。一般向けの本でも掲載する画像・説明を確認する。

ShushukaAdminの管理対象をISBNごとの表紙・紹介文と、シリーズごとのランキング公開情報に分ける。公開用の一般作品判定を巻の全画像に流用しない。

| 表示内容の状態 | 設定ON | 設定OFF |
| --- | --- | --- |
| 確認済み・掲載可 | 確認した表紙・紹介文を表示 | 非表示 |
| 掲載不可 | 非表示 | 非表示 |
| 未確認／判定取得失敗 | 非表示、管理用の文字情報は残す | 非表示 |

未確認を非表示にする方式を採用すると、確認していない新しい本は当面表紙・紹介文が出ない。現在の公開ランキング3作品の確認は、そのシリーズの全巻の表紙・説明を確認したことにはならない。この影響を説明し、実装への了承を受けた。

## 実装上の注意

- 共通BookCoverがURL失敗時に楽天・OpenLibraryの画像へ自動で切り替える。非表示対象では画像URLを一つ消すだけでは不十分。画像取得と代替画像への切替の両方を止める。
- 本の詳細は複数の取得元から紹介文を統合する。確認した紹介文だけを使用し、別の取得元の未確認の説明文を差し戻さない。
- 掲載可の判定はISBNだけでなく、確認した画像URL・説明文の版に結び付ける。画像や説明が更新されたら再確認する。
- 利用者が編集した画像URLを管理者確認済みとして扱わない。一般利用者は判定を書き換えられない。
- 従来の補正APIの情報を表示承認として使わない。専用のreviewed_book_contentテーブルから確認済みの内容を読み取る。
- 公開ランキングはすでに管理者確認済みかつadult_only=falseの場合のみ表示する。個人の表示設定からこの条件を変更しない。

## 申請との関係

年齢区分は設定ONの場合も含めた表示可能な内容で回答する。OFFが選べること、初期値がOFFであることだけを根拠に「なし」としない。

Apple審査基準1.2には、Web由来のユーザ生成コンテンツについて、偶発的なNSFW内容は初期非表示かつWebサイトで利用者が表示を有効にする条件がある。これは今回の私用書誌情報の扱いを自動的に許可する規定ではなく、アプリ内スイッチだけで同じ条件を満たすとも判断しない。

年齢区分を高くすることや表示切替は、露骨な性的画像・紹介文の掲載許可を意味しない。掲載条件を確認し、表示対象を決めてから頻度項目を確定する。

公式参考：
- https://developer.apple.com/app-store/review/guidelines/#objectionable-content
- https://developer.apple.com/app-store/review/guidelines/#user-generated-content
- https://developer.apple.com/help/app-store-connect/reference/app-information/age-ratings-values-and-definitions

## 実装・運用

- `reviewed_book_content` はISBNごとの確認済みの画像URL・紹介文そのもの・確認元・有効状態を保存する。APIが後から返す別の画像や紹介文に承認を流用しない。一般利用者は読取りのみ、有効な行だけ取得可能。管理者はサービス権限で保存する。
- 初期データの自動承認はしていない。確認完了まで既存の本も表紙・紹介文が非表示になる。ISBNのない本は確認済み画像URLと一致する場合だけ表示できる。
- 共通BookCoverで全画面の画像を制御する。確認済み画像の取得失敗でも楽天・OpenLibraryへ切り替えない。詳細画面は確認済み紹介文のみ表示する。
- 確認情報は50件ずつまとめて取得し、画面切替時にまとめる。表示中は60秒ごと、アプリ復帰時にも再取得。通信失敗・設定読込み前・設定OFFは非表示。無効化の反映には最大約60秒と通信時間がかかる。端末への確認情報の永続保存はしない。
- ShushukaAdminに「表紙・紹介文」 `/content` と「ランキング」 `/rankings` を追加。既存の管理者認証の後ろに配置し、新しい保存操作にはCSRFトークンを必須にする。成人向け・未確認のランキングは掲載ONで保存しても非掲載になる。
- URL先の画像そのものは外部サービスの配信物であり、同じURLの内容変更を検出する機能はない。運用で再確認・無効化する必要がある。画像ファイルを固定して管理する方式は未実装。
- 型チェック、表示制御・画像失敗時のテスト、管理画面のCSRF・URL形式・成人向け除外テストは成功。本番DBの読取り制限と一般利用者の書込み権限も検証済み。
- App Storeで選択済みのビルド15には含まれない。新ビルドの実機確認・年齢区分の確定・審査送信は未実施。
